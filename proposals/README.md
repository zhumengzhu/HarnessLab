# Proposals

This directory stores improvement proposals generated by
`harnesslab propose`. Proposals are **advisory**: they are never
applied automatically. They exist so that recurring failure clusters
in real traces or eval runs become reviewable, deduplicated, and
auditable artifacts in the repo's history.

## File layout

Each proposal is a markdown file named `prop_<YYYYMMDDhhmm>_<sig8>.md`,
where `sig8` is the first 8 hex chars of `sha1(cluster_signature)`.
The leading `prop_` plus stable `sig8` mean re-running `propose` on
the same recurring failure does not produce duplicate files; the
generator dedupes against any proposal whose front-matter has
`status: open`.

YAML front-matter pins the machine-readable bits:

```yaml
---
id: prop_2026_05_23_a3f2c1
status: open            # open | accepted | rejected | superseded
kind: policy_denial
cluster_signature: "tool_denied:run_shell_safe:command not in allowlist"
occurrences: 7
generated_at: 2026-05-23T22:47:00+00:00
related_files:
  - src/harnesslab/policy/default_policy.py
---
```

The body sections (Cluster, Sample events, Suggested actions,
Acceptance checklist) are for humans.

## Workflow

1. Generate:
   ```bash
   uv run harnesslab propose \
       --trace .harnesslab/trace.jsonl \
       --eval-report eval/reports/latest.json
   ```
2. Review the generated files in `proposals/`.
3. Decide:
   - **Accept**: edit `status: accepted`. If you also patched code, the
     fix commit message should reference the proposal id.
   - **Reject**: edit `status: rejected` and add a short `## Decision`
     section explaining why. The cluster signature stays on file so
     future runs don't keep raising the same dead-end suggestion.
   - **Supersede**: edit `status: superseded` and link to the proposal
     that replaces it.
4. A proposal may move to `accepted` only after all four items in its
   "Acceptance checklist" are satisfied — including
   `uv run harnesslab eval` showing no baseline regression. That step
   is the Step 4 regression gate the roadmap requires.

See `AGENTS.md` "Proposal Handling" for the binding contract that
governs how AI agents (including this repo's coding assistant) may and
may not interact with proposals.
